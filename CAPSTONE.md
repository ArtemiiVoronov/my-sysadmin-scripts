# Часть 2. Архитектурные решения

## 1. Почему выбран вариант скрипта B?

Вариант B (Setup-скрипт) выбран потому, что он:
- Автоматизирует реальную задачу администрирования — создание пользовательского окружения.
- Даёт возможность продемонстрировать работу с аргументами, проверкой ошибок и логированием.
- Хорошо ложится на Docker: не требует интерактивного ввода, легко передавать аргументы.
- Логичен для последующей контейнеризации и расширения (HTTP-сервер, том, автозапуск).

## 2. RAID 1 vs LVM

Использованы **оба** инструмента, потому что у них разные задачи:
- **RAID 1** (зеркалирование) — отказоустойчивость. Если один диск выйдет из строя, данные сохранятся.
- **LVM** — гибкость. Позволяет расширять логический том, добавлять диски в пул и управлять размером без остановки сервиса.

Логика выбора: сначала RAID (физическая надёжность), затем LVM поверх (гибкость управления). Так делают в реальных компаниях. Альтернативой был RAID 0 (скорость без надёжности) или RAID 5 (чётность, но требует минимум 3 диска).

## 3. Способ получения сертификата

Выбран **самоподписанный сертификат** (self-signed), потому что:
- Учебная среда, нет публичного домена.
- Let's Encrypt требует реального домена и внешней валидации.
- Для внутреннего тестирования самоподписанного достаточно.

В проде использовался бы Let's Encrypt через Certbot (ACME-протокол) или корпоративный CA.

## 4. Альтернативы

Рассматривались:
- **RAID 5** — отвергнут: требует минимум 3 диска, у нас 2 loop-устройства.
- **Nginx в контейнере** — отвергнут: сложнее пробрасывать порты и TLS.
- **Let's Encrypt** — отвергнут: нет публичного домена.
- **systemd не для контейнера, а напрямую для скрипта** — отвергнут: Docker уже инкапсулирует всё окружение, а systemd управляет самим контейнером.

## 5. Среда выполнения: собственный сервер на железе

Для выполнения ДЗ использовался **собственный ноутбук**, на который был установлен **Linux (Xubuntu 26.04)** с нуля — с полной заменой Windows. Это соответствует дорожке «Продвинутый» и даёт ряд преимуществ по сравнению с облачным хостом или виртуальной машиной:

- **Реальное железо** — все технологии (RAID, LVM, systemd, Docker) работают нативно, без прослойки виртуализации.
- **Полный контроль** — доступ к BIOS, реальная работа с дисками через loop-устройства, настройка сетевых интерфейсов.
- **Долгосрочное использование** — сервер не «умирает» после сессии, как в Killercoda, и не требует оплаты, как облако.
- **Свобода экспериментов** — можно ломать и переустанавливать без страха потерять важные данные.

### Как настраивался сервер

1. **Установка Xubuntu 26.04 LTS** на ноутбук — с полной заменой Windows.
2. **Установка SSH-сервера** (`openssh-server`) и настройка доступа по ключу (без пароля).
3. **Установка Docker** (`docker.io`, `docker-compose`) и добавление пользователя в группу `docker`.
4. **Установка Nginx** и утилит (`mdadm`, `lvm2`, `curl`, `pandoc`).

### Связка с рабочим местом

Подключение к серверу выполняется **с основного ПК** через **SSH** — это имитирует реальную работу системного администратора, который управляет удалённым сервером. Все команды ДЗ выполняются **на сервере** (ноуте), но **управление** идёт **с** **ПК**.

Такая схема ближе к реальной работе, чем работа на локальной машине: администратор не сидит за сервером, а подключается к нему по сети.

# Часть 3. Что не получилось с первого раза

1. **`тол$` в приглашении** — при настройке PS1 в `.bashrc` escape-последовательности цветов отображались как текст. Исправлено сбросом `.bashrc` из `/etc/skel/` и удалением лишнего `$` в PS1.

2. **RAID из loop-устройств** — `mdadm` не был установлен. Исправлено: `sudo apt install mdadm -y`.

3. **LVM не установлен** — `pvcreate` не найден. Исправлено: `sudo apt install lvm2 -y`.

4. **Скрипт в контейнере писал лог не туда** — `LOG_FILE="setup.log"` записывал в `/` контейнера. Исправлено: `LOG_FILE="$USER_DIR/setup.log"` (лог рядом с данными пользователя).

5. **Дубликат контейнера `my-app`** — при повторном `docker run` была ошибка `container name already in use`. Исправлено: `docker rm -f my-app`.

6. **Установка Linux без флешки** — USB-накопитель оказался бракованным (не определялся ни в BIOS, ни в Windows). Решение: использован ISO-образ на разделе диска + `bcdedit` для добавления записи в загрузчик Windows. Загрузка установщика Xubuntu через `Boot From EFI File` → `\EFI\BOOT\BOOTx64.EFI`.

7. **Зависшие блокировки apt** — при установке `pandoc` процессы `apt` зависли на `/var/lib/dpkg/lock-frontend`. Решение: `kill -9` для всех зависших PID, удаление lock-файлов, `dpkg --configure -a`.
